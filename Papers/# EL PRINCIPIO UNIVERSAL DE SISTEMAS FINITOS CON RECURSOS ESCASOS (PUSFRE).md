## CAPÍTULO 0: EL PROBLEMA DE LOS DISFRACES

### 0.1 Por qué los Sistemas son Todos Iguales

Hay una lección que la mayoría de los ingenieros aprenden tarde, si es que la aprenden:

> **Un sistema que asigna recursos escasos entre partes finitas es matemáticamente idéntico a cualquier otro sistema que asigne recursos escasos entre partes finitas, independientemente de lo que las partes se llamen o de lo que los recursos sean.**

No importa si las partes son agentes, vehículos, generadores eléctricos, medicamentos, cultivos, servidores, frecuencias de radio, o departamentos de un hospital. No importa si el recurso es contexto, presupuesto, ancho de banda, energía, tiempo, atención, o espacio de almacenamiento.

La estructura es siempre la misma.

El problema siempre es el mismo.

La solución siempre es la misma.

Este capítulo explica por qué.

### 0.2 La Estructura Oculta de Todos los Sistemas

Cualquier sistema que cumpla estas condiciones:

1. **Tiene un número finito de partes.**
2. **Tiene un recurso escaso.**
3. **Cada parte necesita una cantidad positiva del recurso para existir.**
4. **El sistema evoluciona en el tiempo.**
5. **El sistema es inherentemente ruidoso.**

Tiene la misma estructura matemática.

Y esa estructura es el PUSFRE.

### 0.3 El Mapa del Territorio (No el Territorio)

El PUSFRE no es el sistema. Es el mapa del sistema.

**Solo necesitas conocer cinco cosas:**

1. Cuántas partes tiene el sistema.

## CAPÍTULO 1: LA ECUACIÓN QUE LO GOBIERNA TODO

### 1.1 La Ecuación Maestra Universal

En el PUSFRE, la fitness de cualquier parte del sistema se calcula con una única ecuación:

$$ F_i = \Phi_i \cdot \Psi_i \cdot \Omega_i^\alpha \cdot \epsilon_i $$

Donde:

- **$F_i$** es la fitness de la parte $i$.
- **$\Phi_i$** es la capacidad de la parte $i$ para usar el recurso.
- **$\Psi_i$** es la consistencia de la parte $i$.
- **$\Omega_i$** es la frecuencia de invocación de la parte $i$.
- **$\alpha$** es el exponente de competencia.
- **$\epsilon_i$** es el ruido estocástico.

### 1.2 La Interpretación Universal de Cada Término

Cada término de la Ecuación Maestra tiene una interpretación universal que se aplica a cualquier sistema finito con recursos escasos:

#### 1.2.1 $\Phi_i$ — La Capacidad (La Pared)

**Definición universal:** $\Phi_i$ mide la capacidad de la parte $i$ para utilizar el recurso de manera efectiva. Es una propiedad intrínseca de la parte, independiente del estado del sistema.

**Interpretación por dominio:**

| Dominio | $\Phi_i$ significa |
|---|---|
| Logística | Capacidad de la flota / vehículo |
| Finanzas | Rendimiento esperado del activo |
| Energía | Eficiencia del generador |
| Salud | Capacidad del departamento |
| Ciberseguridad | Valor del activo |
| Telecomunicaciones | Cobertura de la estación base |
| Agricultura | Rendimiento del cultivo |
| Retail | Rotación del producto |

#### 1.2.2 $\Psi_i$ — La Consistencia (El Filtro)

**Definición universal:** $\Psi_i$ mide la consistencia de la información o el estado de la parte $i$. Mayor inconsistencia reduce la utilidad del recurso asignado.

$$ \Psi_i = 1 - \gamma \cdot \bar{D}_i $$

Donde $\bar{D}_i$ es la inconsistencia media de la parte $i$ y $\gamma$ es un coeficiente de penalización.

**Interpretación por dominio:**

| Dominio | $\Psi_i$ significa |
|---|---|
| Logística | Confiabilidad de la ruta |
| Finanzas | Riesgo del activo |
| Energía | Estabilidad del generador |
| Salud | Calidad del servicio |
| Ciberseguridad | Vulnerabilidad del activo |
| Telecomunicaciones | Calidad de la señal |
| Agricultura | Calidad del suelo |
| Retail | Consistencia del inventario |

#### 1.2.3 $\Omega_i$ — La Frecuencia (El Ritmo)

**Definición universal:** $\Omega_i$ mide la frecuencia con la que la parte $i$ es invocada o utilizada. Es una propiedad dinámica que evoluciona con el sistema.

$$ \Omega_i = N_i^\alpha $$

Donde $N_i$ es la frecuencia normalizada y $\alpha$ es el exponente de competencia.

**Interpretación por dominio:**

| Dominio | $\Omega_i$ significa |
|---|---|
| Logística | Uso de la ruta |
| Finanzas | Participación en la cartera |
| Energía | Carga del generador |
| Salud | Ocupación del departamento |
| Ciberseguridad | Exposición del activo |
| Telecomunicaciones | Tráfico de la estación |
| Agricultura | Producción del cultivo |
| Retail | Demanda del producto |

### 1.3 La Asignación Óptima de Recurso

Dada la fitness de cada parte, la asignación óptima de recurso es:

$$ r_i = R \cdot \frac{F_i}{\sum_{j=1}^{N} F_j} $$

Donde:

- $r_i$ es el recurso asignado a la parte $i$.
- $R$ es el recurso total disponible.
- $N$ es el número de partes.

Esta asignación es la que maximiza el beneficio total del sistema sujeto a la restricción de coexistencia.

### 1.4 La Condición de Coexistencia

La coexistencia (todas las partes tienen recurso positivo) es posible si y solo si:

$$ k \geq S \cdot \frac{\max_i \Phi_i \Psi_i}{\min_j \Phi_j \Psi_j} \cdot \frac{1}{\ln(S/\delta)} $$

Donde:

- $k$ es el tamaño del batch de asignación.
- $S$ es el número de partes.
- $\delta$ es la probabilidad máxima tolerable de exclusión.

### 1.5 La Dinámica Temporal

El sistema evoluciona en el tiempo según:

$$ r_i(t+1) = R \cdot \frac{F_i(t)}{\sum_{j=1}^{N} F_j(t)} $$

El sistema converge a un punto fijo $\mathbf{r}^*$ que satisface:

$$ r_i^* = R \cdot \frac{F_i(\mathbf{r}^*)}{\sum_{j=1}^{N} F_j(\mathbf{r}^*)} $$

## CAPÍTULO 2: LAS CINCO HERRAMIENTAS UNIVERSALES

### 2.1 El Arsenal del Arquitecto

El PUSFRE proporciona cinco herramientas universales que resuelven cualquier sistema finito con recursos escasos:

1. **La Ecuación Maestra** → Calcula la fitness de cada parte.
2. **El Planificador en U** → Prioriza partes según posición y capacidad.
3. **El Teorema de Coexistencia-$k$** → Garantiza que todas las partes sobrevivan.
4. **La Detección de Subgrafos Anómalos** → Identifica dependencias críticas.
5. **El Muestreo Estratificado** → Estima parámetros de manera eficiente.

Cada herramienta es independiente. Pero juntas son imparables.

### 2.2 La Ecuación Maestra (La Brújula)

**Qué hace:** Calcula la fitness de cada parte del sistema.

**Cuándo se usa:** Siempre. Es el punto de partida de cualquier análisis PUSFRE.

**Cómo se usa:**

```python
def fitness(phi, psi, omega, alpha, epsilon):
    return phi * psi * (omega ** alpha) * epsilon
```

**Interpretación universal:**

| Símbolo | Significado | Rango |
|---|---|---|
| $\Phi$ | Capacidad | $[0, 1]$ |
| $\Psi$ | Consistencia | $[0, 1]$ |
| $\Omega$ | Frecuencia | $[0, 1]$ |
| $\alpha$ | Competencia | $[0.5, 2.5]$ |
| $\epsilon$ | Ruido | $\text{LogNormal}(0, \sigma^2)$ |

**Koan de la Brújula:**
*El discípulo preguntó: "Maestro, ¿cómo sé hacia dónde ir?"*
*El maestro respondió: "Calcula la fitness de cada camino. El que tenga mayor fitness te llevará adonde necesitas ir."*
*"¿Y si no sé adónde necesito ir?"*
*"Entonces la fitness te dirá lo que es mejor para ti, incluso si no lo sabes."*

### 2.3 El Planificador en U (La Partitura)

**Qué hace:** Prioriza partes según su posición en una secuencia, dando más prioridad a las que están en los extremos.

**Cuándo se usa:** Cuando la posición de una parte en la secuencia de asignación afecta su utilidad.

**Cómo se usa:**

```python
def attention(position, total):
    p = position / total if total > 0 else 0
    primacy = 0.4 * exp(-5 * p)
    recency = 0.4 * exp(-5 * (1 - p))
    valley = 0.2
    return primacy + recency + valley
```

**Interpretación universal:**

| Dominio | "Posición" significa |
|---|---|
| Logística | Orden en la ruta |
| Finanzas | Orden en la cartera |
| Energía | Orden en el despacho |
| Salud | Orden en la cola de pacientes |
| Ciberseguridad | Orden de prioridad de parches |
| Telecomunicaciones | Orden de asignación de frecuencia |

**Por qué funciona:** La atención en U es una ley universal de los sistemas con memoria finita. Los extremos (primacía y recencia) reciben más atención que el centro (valle). El PUSFRE explota esta ley para priorizar partes de manera óptima.

**Koan de la Partitura:**

### 2.4 El Teorema de Coexistencia-$k$ (El Guardián)

**Qué hace:** Garantiza que todas las partes del sistema tengan recurso positivo.

**Cuándo se usa:** Cuando el sistema tiende a la exclusión competitiva (unos pocos dominan, el resto se extingue).

**Cómo se usa:**

```python
def min_batch_size(S, max_fitness, min_fitness, delta):
    ratio = max_fitness / min_fitness
    return int(ceil(S * ratio / log(S / delta)))
```

**Interpretación universal:**

| Símbolo | Significado |
|---|---|
| $k$ | Batch mínimo para coexistencia |
| $S$ | Número de partes |
| $\delta$ | Riesgo máximo de extinción |
| $\text{ratio}$ | Dispersión de fitness |

**La regla de oro:** Si $k$ es menor que el mínimo calculado, algunas partes se extinguirán inevitablemente.

**Koan del Guardián:**
*El discípulo preguntó: "Maestro, ¿cómo sé si todos sobrevivirán?"*
*El maestro respondió: "Calcula el batch mínimo."*
*"¿Y si es demasiado grande?"*

### 2.5 La Detección de Subgrafos Anómalos (El Radar)

**Qué hace:** Identifica dependencias críticas entre partes del sistema.

**Cuándo se usa:** Cuando el sistema tiene una estructura de red (dependencias entre partes).

**Cómo se usa:**

```python
def anomaly_ratio(subgraph_density, expected_density):
    if expected_density == 0:
        return float('inf')
    return subgraph_density / expected_density
```

**Interpretación universal:**

| Dominio | "Subgrafo anómalo" significa |
|---|---|
| Logística | Rutas interdependientes |
| Finanzas | Activos correlacionados |
| Energía | Generadores acoplados |
| Salud | Patologías relacionadas |
| Ciberseguridad | Vulnerabilidades encadenadas |
| Telecomunicaciones | Canales interferentes |

**Por qué funciona:** En cualquier sistema con estructura de red, hay subconjuntos de partes que están densamente interconectados. Estos subconjuntos son puntos críticos de vulnerabilidad o eficiencia. La detección de subgrafos anómalos los identifica.

**Koan del Radar:**
*El discípulo preguntó: "Maestro, ¿cómo sé qué partes son críticas?"*
*El maestro respondió: "Busca las que están densamente conectadas."*
*"¿Y por qué son críticas?"*
*"Porque si falla una, arrastra a las demás."*

### 2.6 El Muestreo Estratificado (El Microscopio)

**Qué hace:** Estima parámetros del sistema de manera eficiente con garantías estadísticas.

**Cuándo se usa:** Cuando no se pueden medir directamente todos los parámetros del sistema.

**Cómo se usa:**

```python
def stratified_sample_size(weights, sigmas, epsilon, delta):
    total = sum(weights * sigmas)
    return int(ceil(log(2 / delta) / (2 * epsilon**2) * total**2))
```

**Interpretación universal:**

| Símbolo | Significado |
|---|---|
| $W_h$ | Peso del estrato $h$ |
| $\sigma_h$ | Desviación en el estrato $h$ |
| $\epsilon$ | Error máximo aceptable |
| $\delta$ | Riesgo de error máximo |

**La garantía:** La estimación tiene error $\epsilon$ con probabilidad $1-\delta$.

**Koan del Microscopio:**
*El discípulo preguntó: "Maestro, ¿cómo sé si mis mediciones son correctas?"*
*El maestro respondió: "Mide estratificadamente."*
*"¿Y cómo sé cuántas muestras tomar?"*
*"Hasta que la garantía sea suficiente."*

## CAPÍTULO 4: EL MANUAL DE OPERACIONES

### 4.1 Diagnóstico Rápido

Para diagnosticar cualquier sistema finito con recursos escasos:

**Pregunta 1:** ¿Cuántas partes tiene el sistema?

**Pregunta 2:** ¿Cuánto recurso hay?

**Pregunta 3:** ¿Qué capacidad tiene cada parte para usar el recurso?

**Pregunta 4:** ¿Qué consistencia tiene cada parte?

**Pregunta 5:** ¿Con qué frecuencia se usa cada parte?

Con estas cinco preguntas, tienes la entrada para la Ecuación Maestra.

### 4.2 El Protocolo de las 5 P

```
PROTOCOLO PUSFRE (5 Pasos)

PASO 1: PARTES
Identifica todas las partes del sistema y el recurso que comparten.

PASO 2: PARÁMETROS
Mide Φ, Ψ, Ω para cada parte.

PASO 3: FITNESS
Calcula F_i = Φ_i · Ψ_i · Ω_i^α · ε_i.

PASO 4: ASIGNACIÓN
Asigna recurso: r_i = R · F_i / ΣF_j.

PASO 5: VERIFICACIÓN
Verifica coexistencia: r_i > ε para todo i.
Si falla, ajusta k.
```

### 4.3 El Checklist del Arquitecto

```
☐ ¿He identificado todas las partes?
☐ ¿He identificado el recurso escaso?
☐ ¿He medido Φ para cada parte?
☐ ¿He medido Ψ para cada parte?
☐ ¿He medido Ω para cada parte?
☐ ¿He elegido α (exponente de competencia)?
☐ ¿He calculado la fitness de cada parte?
☐ ¿He asignado recurso proporcionalmente?
☐ ¿He verificado coexistencia?
☐ ¿He documentado la solución?
```

### 4.4 Errores Comunes (Y Cómo Evitarlos)

| Error | Síntoma | Solución |
|---|---|---|
| Medir Φ mal | Asignación subóptima | Revisar la definición de capacidad |
| Medir Ψ mal | Inconsistencia no penalizada | Asegurar que Ψ ∈ [0,1] |
| Medir Ω mal | Frecuencia mal estimada | Usar muestreo estratificado |
| Elegir α mal | Exclusión o monopolio | Ajustar α según el sistema |
| Ignorar ε | Solución demasiado determinista | Añadir ruido realista |
| Olvidar coexistencia | Algunas partes se extinguen | Verificar k ≥ k_min |
| Ignorar posición | Secuencia subóptima | Aplicar Planificador en U |
| Ignorar red | Dependencias críticas no detectadas | Detectar subgrafos anómalos |

### 5.1 Caso 1: Cadenas de Suministro

```python
"""
PUSFRE — Principio Universal de Sistemas Finitos con Recursos Escasos
Librería ejecutable para cualquier sistema que asigne recursos escasos.
Autor: David Ferrandez · #1310
"""

import numpy as np
from typing import Callable, Dict, Any, Optional, List, Tuple
from dataclasses import dataclass, field

# ============================================================
# 1. ESTRUCTURAS DE DATOS
# ============================================================

@dataclass
class Part:
    """Una parte del sistema."""
    id: int
    phi: float  # Capacidad
    psi: float  # Consistencia
    omega: float  # Frecuencia
    r: float = 0.0  # Recurso asignado
    fitness: float = 0.0  # Fitness calculada

@dataclass
class SystemState:
    """Estado del sistema en un momento dado."""
    parts: List[Part]
    total_resource: float
    step: int = 0
    history: List[Dict] = field(default_factory=list)
    
    def resource_allocation(self) -> np.ndarray:
        return np.array([p.r for p in self.parts])
    
    def fitness_vector(self) -> np.ndarray:
        return np.array([p.fitness for p in self.parts])

class PUSFRE:
    """
    Resuelve cualquier sistema finito con recursos escasos.
    
    El PUSFRE es la implementación operativa del principio universal.
    """
    
    def __init__(self, alpha: float = 1.2, gamma: float = 0.45, sigma: float = 0.15):
        self.alpha = alpha
        self.gamma = gamma
        self.sigma = sigma
        self.rng = np.random.default_rng(42)
    
    def compute_fitness(self, part: Part) -> float:
        """Ecuación Maestra: F = Φ · Ψ · Ω^α · ε"""
        phi = part.phi
        psi = 1.0 - self.gamma * (1.0 - part.psi)  # Si psi=1 → sin penalización
        omega = part.omega ** self.alpha if part.omega > 0 else 0.01 ** self.alpha
        epsilon = self.rng.lognormal(0, self.sigma)
        return phi * psi * omega * epsilon
    
    def allocate(self, system: SystemState) -> SystemState:
        """Asigna recurso proporcionalmente a la fitness."""
        # Calcular fitness de cada parte
        for part in system.parts:
            part.fitness = self.compute_fitness(part)
        
        # Asignar recurso
        total_fitness = sum(p.fitness for p in system.parts)
        if total_fitness > 0:
            for part in system.parts:
                part.r = system.total_resource * part.fitness / total_fitness
        
        system.step += 1
        system.history.append({
            'step': system.step,
            'allocation': system.resource_allocation().copy(),
            'fitness': system.fitness_vector().copy()
        })
        
        return system
    
    def solve(
        self,
        n_parts: int,
        total_resource: float,
        phi: np.ndarray,
        psi: np.ndarray,
        omega: np.ndarray,
        max_iter: int = 1000,
        tol: float = 1e-6
    ) -> Dict[str, Any]:
        """Resuelve el sistema completo."""
        # Inicializar partes
        parts = [
            Part(id=i, phi=phi[i], psi=psi[i], omega=omega[i])
            for i in range(n_parts)
        ]
        
        # Asignación inicial uniforme
        for part in parts:
            part.r = total_resource / n_parts
        
        system = SystemState(parts, total_resource)
        
        for iteration in range(max_iter):
            old_allocation = system.resource_allocation().copy()
            system = self.allocate(system)
            new_allocation = system.resource_allocation()
            
            # Verificar convergencia
            delta = np.max(np.abs(new_allocation - old_allocation))
            if delta < tol:
                return {
                    'system': system,
                    'iterations': iteration + 1,
                    'converged': True,
                    'final_allocation': new_allocation,
                    'final_fitness': system.fitness_vector(),
                    'history': system.history
                }
        
        return {
            'system': system,
            'iterations': max_iter,
            'converged': False,
            'final_allocation': system.resource_allocation(),
            'final_fitness': system.fitness_vector(),
            'history': system.history
        }
    
    @staticmethod
    def coexistence_check(allocation: np.ndarray, epsilon: float = 1e-6) -> bool:
        """Verifica que todas las partes tengan recurso positivo."""
        return np.all(allocation > epsilon)
    
    @staticmethod
    def min_batch_size(S: int, max_fitness: float, min_fitness: float, delta: float = 0.01) -> int:
        """Teorema de Coexistencia-k."""
        if min_fitness <= 0:
            return S
        ratio = max_fitness / min_fitness
        return int(np.ceil(S * ratio / np.log(S / delta)))
```
